This reader accepts a complete, independently admitted three-seed Bottles campaign and six new paired final invocations. It does not run a policy, select a checkpoint, or produce a training result. No full campaign currently supplies these inputs. CPU fixtures prove software behavior only.

Run the separate standard-library entry point:

```sh
CUDA_VISIBLE_DEVICES='' python -B -m abc_bench.qf3_campaign_comparison \
  --request /absolute/path/campaign-request.json \
  --request-sha256 ACTUAL_REQUEST_SHA256 \
  --output /absolute/path/new-comparison.json
```

The output path must be new. The writer flushes a temporary file, publishes it with one atomic hard link, and flushes the directory. A rejected comparison publishes no performance report. Existing reports are preserved. The reader imports no Torch, NumPy, Sadhana, simulator or model package. It shares strict byte, JSON and paired-statistic helpers with the unchanged development reader; it uses separate worker, cohort, source and event gates. The legacy reader and its tests remain byte exact.

Every artifact record uses absolute `path`, strict integer `bytes` and lowercase SHA256. Extra producer `kind` labels do not replace these three byte pins. JSON is hashed as the exact bytes parsed; duplicate keys, non-finite numbers and bool-as-int identities refuse. Binary files are streamed without deserialization. A checkpoint admission's booleans are assertions from a separately reviewed audit; this reader does not authenticate a reviewer or manufacture its semantic proof.

The request has schema1 and kind `qf3_full400k_three_seed_comparison_request`. Required fields are `release_wheel`, `independent_install_review`, `native_install_review`, `selection_seal`, `discarded_invocations` and exactly three ordered `seeds` entries. Each seed entry has `index`, `training_chain`, `selection`, `frozen_final` and `learned_final`. There is no caller-supplied source profile or relaxed threshold.

Each training-chain item has `worker`, `parent`, `admission` and `input_preflight` artifact records. The input preflight kind is `qf3_full_campaign_input_preflight`; it binds the input and resolved-config pins, semantic resolved hash, exact continuation, release/install pins and source map, and has separately accepted `actual_installed_resolve` and `artifact_native_source_inventory_pins` checks. The training admission fields are:

- `kind=qf3_full_campaign_checkpoint_admission`, schema1, `status=accepted`, `independent_review=true`, the named checks in the contract, and exact worker/config/controller/predecessor admission pins.
- Exact base, protocol, continuation and source identities; actual admitted complete checkpoint, canonical learner/replay/full-bridge/training-RNG hashes; ordered selector hash and canonical replay metadata.
- `replay_blocks`: sorted, unique artifacts with insertion `first_ordinal`, `record_count` and positive `selector_count`. Selectors sum to canonical ring size; empty references refuse. Rows inside a referenced block can remain unused after eviction. Tensor, selector and row semantics remain the separate audit's responsibility.
- `boundary`: strict warmup/outer/control/physics/episode/evaluation counters, complete phase, partial=false and canonical evaluation state (`history`, cursor, threshold, baseline and pending intent). `counters` binds critic, actor and target schedules.
- `accepted_tapes`: newly accepted warmup/train entries in exact ordinal order. Each contains `category`, `ordinal`, `artifact`, `source_sha256` and `accounting` (episode/control/tick/decision counts, exact episode-ID list and evidence-ID-list hash). `covered_training_tape_sha256` is the ordered cumulative lineage, including earlier admitted tapes that cover evicted features.
- `fresh_tapes`: newly accepted event-index/artifact/noise-RNG-hash/full-policy-hash bindings. Each event binds its immutable manifest and public randomization reset files. Actual fresh outcomes are recomputed from executed events.
- `discarded_tapes`: exact artifact/accounting records for unaccepted attempts. Attempted controls are retained but give no accepted checkpoint credit. `invocation_accounting` contains accepted and discarded deltas, accepted/discarded critic and actor updates, and newly accepted fresh controls/ticks.

An intermediate complete checkpoint may precede its outer's validation or contain its pending immutable manifest. It may resume only through a separately accepted boundary audit. Its successor must preserve the manifest/noise identity and complete the missing event before it gains another outer. A resume that completes pending validation can have zero new training/update deltas. The selected first-target boundary must have all K fresh50 events and pending=null. No later target-qualified snapshot is accepted. Warmup batch progress cannot skip or repeat. The initial invocation starts fresh; later inputs resume the exact previous admitted bytes. Discarded rows and optimizer progress cannot be inherited as accepted credit.

`discarded_invocations` retains separate unadmitted controller attempts with `seed_index`, `parent`, `input_config`, optional `worker`, nonempty `reason` and `accepted_counter_credit=0`. Their actual parent elapsed time is reported. They provide no performance outcome or counter credit. An incomplete/failed invocation can contribute a complete boundary only through the separate checkpoint admission and its complete raw evidence. An absent failure receipt or missing elapsed measure cannot be reconstructed by this reader.

Each selection record uses `qf3_full_campaign_checkpoint_selection` and binds the actual selected admission/checkpoint/receipt/config, full policy hash, exact counter-only first-target rule and timezone-aware selection time. The single `qf3_full_campaign_selection_seal` pins all three selections and exact final protocol. All selections must precede the seal; the seal must precede the earliest start of all six final invocations. Consistent timestamps and hashes do not prove access isolation or prior existence.

Each final entry has `worker`, `parent` and `input_preflight`. The learned entry also has `preservation_admission`, kind `qf3_learned_final_preservation_admission`. It binds the selected training admission/checkpoint and final worker/config/controller/evidence-only checkpoint, exact block references and before/after learner/replay/bridge/training-RNG hashes. Named independent checks must accept actual selected resume and saved-state preservation. Equal worker-reported hashes alone are insufficient. No native-world restore is claimed.

Final invocations must each have exactly one new invocation-only event, reason=final, and one newly retained complete50 tape. Frozen runs anew with zero updates and no resume. Learned resumes the selected first-target checkpoint with the exact training continuation and counters. The fixed final cohort is `2**50+j*200001`; pairing requires requested and actual fallback seeds in the same order. Configured noise, grouping and source match; current tapes do not retain raw Gaussian draws or final public reset geometry. The reader does not claim regenerated noise, equal physical geometry or numerical repeatability.

The placement tracker begins at five false values. Reset predicates grant no reward or termination. The first executed step can credit an initially placed object if that step still observes it placed. The reader recomputes history success and first-placement rewards, while reporting native-current success at that history-defined episode end. It reports failure-inclusive lengths, null means for empty success sets, paired wins/losses/both/neither and common-success length deltas. Across three training seeds it reports arithmetic mean and population standard deviation. An undefined seed length mean makes the three-seed length mean/std null. It does not pool150 worlds as independent training trials or infer a causal gain.

Training selection requires actual post-warmup controls >=400000, complete80x4 warmup, complete16-world outer rollouts, Kx1600 critic64 and Kx200 actor256 updates, complete fresh50 at every outer, true target flag and the first qualifying boundary. Both warmup-plus-training and post-warmup axes are reported. Additional400k is a declared reconstruction: paper warmup inclusion and exact initializer remain unresolved. Capture168x224/model pad224, reset and sampler choices remain declared; source equality is not empirical physics equality.

CPU fixtures use actual JSON-shaped events and submitted-control arrays. The bounded three-pair orchestration fixture uses a test-only6080 threshold with26/28/30 outers; production CLI constants stay400000 and cannot be overridden. Corruption tests exercise actual400k refusal below target, canonical counters, block pins, fresh/pending/noise lineage, inherited final summaries, independent saved-state admission and atomic byte publication. These are software tests, not native receipts or model/tensor audits.

Canonical counters bind the selected checkpoint's retained measurements; raw counters retain every attempted control. Strict final target flags bind the learned and frozen states. The original contract/proposal bytes stay unchanged.

No GPU work is needed to run the reader. It reads one simulation tape at a time, but decode memory grows with one tape and one worker JSON log. Streaming the8.8GB candidate and checkpoint/block refs can repeat across invocations. Full-campaign CPU I/O, runtime and peak memory remain unmeasured. Parent elapsed time is authoritative; phase sums do not provide a runtime estimate. Raw tapes, old checkpoints and incomplete attempts remain untouched.
